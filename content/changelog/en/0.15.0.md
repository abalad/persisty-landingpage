---
title: Rename and move files without breaking imports
version: 0.15.0
date: 2026-11-24
---

Renaming and moving files now updates the imports in the files that use them, and the editor shows where a file is used before you move or delete it. The keys below are the default (WebStorm) keymap on the Mac; on Windows and Linux, Option becomes Alt. Everything is also in the command palette and in Settings › Shortcuts.

### Added

- **Rename and move update the imports.** This works with Shift + F6 in the tree and on the tab, F6 in the tree, dragging, and cut and paste. Before touching the disk, the editor asks the language server and, when there are imports to change, shows a preview of the files that will change, each with a checkbox. Enter confirms and Escape cancels; unchecking everything only renames.
  - The notice says how many imports changed and which files were left out.
  - If the server doesn't answer in time, the file is still moved, and the notice explains why the imports weren't updated.
  - Copying leaves the imports alone.
- **Find usages of a file** (Option + F7 in the tree and on the tab). The Usages panel lists the files that import it, through the language server (TypeScript, JavaScript and Rust). When the server doesn't answer, the editor runs a text search instead, and the panel's title says so. Inside the code, the same key still finds the usages of a name.
- **Deleting a file that others import tells you where it's used.** The confirmation lists up to 10 places, with the file and the line, and the button becomes "Delete anyway". The warning only appears when the language server answers within 3 seconds; if it takes longer, you get the usual confirmation.
- **Move to a new file** (the TypeScript server's action), in Option + Enter and in "Refactor This…": the declaration at the cursor, or the selected code, goes to a new file, which opens in a tab. The server's other actions that create, rename or delete files now work too:
  - a deleted file goes to the Trash;
  - an overwritten file stays in the local history;
  - tabs follow the renamed or deleted file.
- **Inspect Code**, in the menu of a file, a folder or a selection in the tree, in the tab menu and in the palette. The language server analyzes the files, open or not (up to 2,000 per project). Problems show up in an "Inspection" section of the Problems panel, grouped by file with errors first.
  - While it runs, the section shows the progress ("20 of 45 files") and has Cancel and Close buttons.
  - Clicking a problem takes you to the line.
  - Files the server didn't get to analyze are left out, and the section says how many.

These actions need a language server for the file's type. Without one, rename and move work as before, without touching the imports.

### Fixed

- **"AI usage — all projects", in the palette, opens the usage of every project,** not just the selected project's. "Open detailed usage", in Settings › AI usage, opens all of them too; the one in the project settings and "Usage details" in the Details panel still open the project.
- **The language chosen in Settings › Appearance holds when you open the app again,** in the mascot's window too. Before, the interface went back to Portuguese.
- **With no IDE chosen, the "Open in" notice points to the right place:** Settings › Workspace › Default IDE.
