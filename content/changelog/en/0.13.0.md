---
title: Git for every file, and a split editor
version: 0.13.0
date: 2026-11-16
---

The editor now shows each file's Git history line by line, and opens files side by side in up to four tab groups.

### Added

- **Who changed each line.** At the end of the cursor's line you see the author, the date and the commit message. Hover it and the commit card offers Copy hash, Show commit and Open on the forge. From the keyboard, use "Show the commit card of the line" in the command palette. You can turn it off or change its format in Settings › Editor.
- **Annotate with git blame.** The gutter shows each line's author and date, colored by the commit's age.
- **Git submenu in the tree and on the tab.** Diff, history of the file and of the selection, compare with a branch or a commit, stage, unstage, discard and annotate. Diffs and history open in read-only tabs.
- **Discarding saves a restore point first**, and the file comes back from the Restore points panel.
- **Split the editor** to the right and down, in up to four groups, each with its own tabs. The same file in two groups stays in sync. Maximize the editor (Command + Shift + F12 on Mac, Control + Shift + F12 on Windows and Linux) hides the terminal to make room.
- **Drag tabs** to reorder them, take them to another group, or drop them on a group's edge to create a new one. Shift + Enter in the tree opens the file on the right.
- **Move a tab with the keyboard.** Option + Shift + Left or Right Arrow (Alt + Shift on Windows and Linux), and "Move the tab to the next group" from the palette.
- **Pin tabs.** A pinned tab stays on the left, with a pin, and is not closed by "Close others", "Close all" or the tab limit.
- **Settings › Editor › Tabs.** Tab limit, where to go when closing, where to open a new tab, the folder in repeated names, the unsaved mark and the preview tab.
- **Dragging in the tree shows what moves and where it lands.** The item's name follows the pointer, the dragged items fade and the target folder is highlighted. Where you cannot drop, Persisty says why.

### Fixed

- **A session with work running in the background** (subagents or commands still running) keeps showing "Working" until the work is done, instead of looking stopped. The queue and the done notice wait for the real end.
- **When you switch sessions,** what you type right away goes to the terminal, never to the file open in the Code panel.
- **Closing several tabs no longer stops at a conflict.** Only the conflicting tab stays open, and one notice says which tabs stayed.
- **A Replace that fails** says which item was not placed and that the old version went to the Trash. After an operation that fails or is undone, tabs return to the same group and position.
- **Copy path with many files** asks Git only once, and "Open on GitHub" on a branch that was never pushed points to the commit.
- **Dragging in a large tree** is much lighter.
- **A key that does not apply in that place** says why, instead of doing nothing.
- Many details in the right-click menus, the tabs, the file history and screen reader support.

On Windows, Undo from the Recycle Bin and the file-in-use notices are still being checked on real machines.
