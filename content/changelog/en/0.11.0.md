---
title: New, Open in and Copy path in the editor's file tree
version: 0.11.0
date: 2026-11-12
---

The editor's file tree got the menu it was missing: create files from templates, open in Finder, a terminal, your IDE or GitHub, copy the path and reload from disk. The tab got every way to close.

### The file tree

- **New** also creates TypeScript, JavaScript, HTML, CSS, JSON, Markdown, Dockerfile and EditorConfig files, with a minimal template already in.
- **Open in**, in the tree and on the tab: Finder, a terminal in the folder, the default app, the browser, your IDE at the current line and the file's page on GitHub, GitLab or Bitbucket.
- **Copy path** and **Copy reference**, in the tree, on the tab and in the editor: the absolute path, the path from the project, the name, `file:line` and the GitHub, GitLab or Bitbucket link (<kbd>Command</kbd> <kbd>Shift</kbd> <kbd>C</kbd> and <kbd>Option</kbd> <kbd>Command</kbd> <kbd>Shift</kbd> <kbd>C</kbd>).
- **Reload from disk**, in the tree and on the tab, and <kbd>Option</kbd> <kbd>Command</kbd> <kbd>Y</kbd> to sync the tree with what changed in the folder.
- <kbd>Command</kbd> + click and <kbd>Shift</kbd> + click select several items, and the keyboard moves through the tree and opens the menu (<kbd>Shift</kbd> <kbd>F10</kbd>).

### Tabs and shortcuts

- Right-clicking an editor tab closes it, the others, all of them, the unmodified ones, or those to its left or right. Only tabs with unsaved changes ask, in a single question.
- **Settings › Shortcuts** has a new Files group, with where each key works: in the tree, on the tab or in the editor.

### Fixed

- When an account ran out of quota again right after renewing, the queue could type "continue" before the next renewal. Now it waits until it knows the new time.
- With autosave on, closing an edited tab asked whether to discard, but saved the changes anyway. Now closing saves without asking, as autosave promises. With it off, the question stays, and **Discard** saves nothing.
